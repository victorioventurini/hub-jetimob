# Memory: features/tickets/notification-context-standard
Updated: 2026-03-20

As notificações do módulo de Tickets são enriquecidas com contexto detalhado para evitar assuntos genéricos. Cinco gatilhos de banco de dados (`notify_ticket_status_changed`, `notify_ticket_created`, `notify_ticket_assigned`, `notify_ticket_message_created`, `notify_ticket_mention`) capturam e passam metadados contextuais via `p_metadata`: `ticket_title`, `ticket_type` (Interno/Externo), `category_name`, `subcategory_name`, `actor_name`, `bu_name`, e labels de status traduzidos via a função imutável `ticket_status_label(text)` (waiting→Aguardando, in_progress→Em andamento, done→Concluído, paused→Pausado, discarded→Descartado). O `p_title` no `emit_notification_event` deve ser o **título real do ticket**, garantindo que o assunto do e-mail siga o padrão `[{{bu_name}}] {{ticket_title}} — {{new_status}}`. Os 4 templates de email (`ticket.status.changed`, `ticket.created`, `ticket.assigned`, `ticket.message.created`) incluem tipo, categoria/subcategoria e ator da ação no corpo. Nenhuma alteração de frontend ou Edge Function é necessária — o sistema é server-side via `p_metadata` → `templateVars`.
